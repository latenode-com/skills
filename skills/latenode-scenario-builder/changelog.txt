### operators.md — КРИТИЧНЫЙ БАГ, исправлено
Почти все имена функций/операторов были в нижнем регистре (`ifempty`, `tolower`,
`matchespattern`, `parsedate`, `formatdate`, `addminutes/hours/days/months`,
`getglobalvar`, `parsenumber`, `formatnumber`, `startswith`, `endswith`, `indexof`,
`encodeurl`, `decodeurl`, `escapemarkdown`, `jsonstringify`, `fromaiagent`, `frommcp`)
вместо правильного camelCase (`ifEmpty`, `toLower`, `matchesPattern`, `parseDate`,
`fromAIAgent` и т.д.) — единственное исключение, сохранившее верный регистр, было
`askAI`. Раздел шаблонов сам описывает движок как регистро-чувствительный (сравнение
строк case-sensitive), поэтому агент, собирающий сценарий по этой версии файла, писал
бы `{{ ifempty(...) }}` и получал ошибку на реальной платформе — функция с таким
именем не существует. Восстановлено 1:1 с оригиналом обычного агента
(copilot-skill-template-evaluator.txt) + добавлено явное предупреждение о регистре в
начале раздела "Functions". Также исправлен синтаксис доступа к данным в таблице
"Data access syntax" — было упрощено до `$N.path` (без backtick-полей), не совпадало
ни с оригиналом, ни с остальными MCP-файлами (SKILL.md, iterator_node.md,
ai_agent_node.md используют `` $N.`field` ``) — приведено к единому виду.

### connections.md — добавлен отсутствовавший тул `create_connection`
Файл описывал только `search_connections` (поиск существующих коннектов), но не
создание новых. Добавлено полное описание `create_connection` по официальной MCP
Tools Reference (documentation.latenode.com/mcp-server/tools): параметры
(`typeAlias`, `title`, `parameters`), вывод (`connectionId`, `url`), и важное
поведенческое отличие от обычного агента — для OAuth-сервисов тул возвращает URL,
который пользователь должен открыть вручную (в обычном агенте это скрыто внутри
визуального виджета `request_connection`).

### js_code_node.md — исправлено ложное "FORBIDDEN"
Раздел "Reading Files from Previous Nodes" помечал `data["{{...}}"]` как
запрещённый паттерн ("WRONG... FORBIDDEN"), хотя официальная документация
(documentation.latenode.com/visual-builder/data-flow/handling-files) показывает
именно этот паттерн (`data["{{2.result.file.content}}"]`) как канонический способ
получить путь к файлу в коде. Переписано: теперь описаны два легитимных варианта —
прямой доступ через шаблон в `data[...]` (по офиц. доке, для быстрого чтения) и
Custom Parameter (когда путь должен быть настраиваемым полем в UI ноды) — с
пояснением, когда какой использовать. Добавлена обязательная последовательность для
трансформации файлов: путь → read → modify → write → `file(...)`.

### working_with_files.md — добавлен официальный паттерн Read→Modify→Write→Return
Раздел про чтение/трансформацию/генерацию файлов в JS-ноде отсутствовал полностью.
Добавлено по официальной доке: получение временного пути через
`data["{{N.result.file.content}}"]`, обязательный порядок get path → read → modify
→ write → return `file(...)` (никогда не возвращать сырой путь как финальный
результат), полный пример на CSV, и совет — просить встроенного AI в JS-ноде
сгенерировать такой код напрямую.

### iterator_node.md — НЕ ИЗМЕНЁН в этом проходе
При живом тестировании через MCP обнаружено: `cycle`-хендл Iterator-ноды (верхний
коннектор, тело цикла) хранится в отдельном, скрытом поле `parameters.nodes`,
которое `create_scenario`/`update_scenario` не позволяют записать — оно доступно
только на чтение через `get_scenario` после того, как соединение сделано вручную в
визуальном UI. Попытка соединить ноду с Iterator через обычный `prevNodes` не
подключает её к `cycle`, а вместо этого приводила к зависанию сценария при тесте.
Вопрос отправлен разработчику платформы — ДО получения ответа никакие формулировки
про это ограничение в сам файл не добавляются (сознательное решение, чтобы не
публиковать неподтверждённую информацию). Статус: ЗАБЛОКИРОВАНО.

### ai_agent_node.md — НЕ ИЗМЕНЁН в этом проходе (тот же принцип)
Обнаружено, что поле `tool_description` для инструментов AI Agent не сохраняется
при передаче как параметр или соседнее поле тула. Есть неподтверждённая гипотеза о
ключе `__$$internal__tool_description` (по аналогии с MCP Trigger node), но она НЕ
подтверждена тестом — вопрос также ожидает ответа разработчика. Статус:
ЗАБЛОКИРОВАНО, файл не трогали.
