# Заметки для разработчиков Latenode MCP

## Статус 2026-09-03

MCP-пакет **базово готов** к сборке сценариев. Механики, которые есть в write API и которые переносили из внутреннего агента, воспроизводятся без обходных путей на холсте: create/update/get, коннекты, Iterator (цикл сверху + правый выход), AI Agent (tools снизу + правый выход), файлы/Gmail, JS, шаблоны `$N` / `_` / `%`, описание Agent Tool, обзорный стикер, именованная ссылка на редактор.

Прогоны живые (same-save и sequential коннекторы, полный демо-граф JS→Gmail, стикер create+update). Содержание скиллов сверено с внутренним агентом; в пакет сознательно не тащили Headless Browser, x/y, чужие тулы вроде `call_mcp_tool`.

Остаётся дырками платформы, не скилла: `substring(...)` в `update_scenario` может дать HTTP 403; API-ключ MCP Trigger не enforced; `get_scenario` может показать `$имя` — писать только `$N`; сценарий целиком через MCP не удалить; стикер всегда падает под граф.

## Как MCP сохраняет особые коннекторы (AI Agent + Iterator)

**Исправлено 2026-09-03.** Write API держит оба коннектора: нижние tools / верхний цикл и обычный правый output в одном `create_scenario` и во втором `update_scenario`.

Прогон:

- Same-save: `6a9929e114868f6504aecc73` — `parameters.nodes` + nested `tools` + `set_variables` справа. Run success: cycle ×3, tools ×1, post-loop ×1.
- Sequential: `6a9929f281ea6a85fb2d21a6` — сначала только цикл/tools, потом правые узлы. После `update` оба особых коннектора на месте. Run success с теми же счётчиками.

На `update_scenario` в шаблонах только `{{$2.value}}` (`$` + номер). `{{$iterator_0.value}}` — не синтаксис платформы. `get_scenario` может *показать* имя; писать его обратно нельзя.

Ниже — история бага 2026-09-01, для регрессии.

MCP не рисует линии на холсте. При сохранении нужно явно указать, какой коннектор использовать.

**Как ломалось до фикса**

Одно сохранение, в котором сразу **два** типа линий:

- особый коннектор (нижний tool или верхнее тело цикла);
- **и** обычный следующий шаг на **правом** коннекторе.

Платформа вешала «особый» узел тоже **справа**. Tool переставал быть tool. Цикл переставал быть циклом. Второе сохранение с правым узлом схлопывало то же самое.

| Что делаем через MCP (до 2026-09-03) | Результат тогда |
|---|---|
| Первое сохранение: только нижний tool (Agent) или верхнее тело цикла (Iterator) | Работает |
| То же сохранение: особый коннектор **и** узел справа | Ломалось |
| Позже отдельным сохранением добавить узел справа | Ломалось |

Тест 2026-09-01:

- Агент `6a969b8914868f6504ae8b8f`: tool1, затем tool2 — оба остались в `parameters.tools`. Следующий `update` с `set_variables` справа схлопнул оба tool в `prevNodes` агента.
- Iterator `6a969b8514868f6504ae8b86`: cycle-only прогон 3 раза. Следующий `update` с `set_variables` справа стёр `parameters.nodes`.

## Tool AI Agent переезжает на обычный выходной коннектор

### Кратко

Создание и обновление tool у AI Agent через `create_scenario` / `update_scenario` ведёт себя непоследовательно.

Tool должен быть подключён через **нижний** коннектор агента. В проблемных запросах тот же узел создаётся через обычный **правый** выход. Граф выглядит связанным, но это уже не Agent Tool:

- `fromAIAgent(...)` падает с `fromAIAgent used outside of the tool`; или
- узел выполняется как обычный следующий шаг, а не как tool, который выбирает модель.

### Как воспроизводилось у пользователя

Создание Agent Tool может пройти, пока у tool нет параметров от модели. После добавления или изменения параметра tool подключение может без явной ошибки смениться с нижнего коннектора на правый.

### Наблюдения в рантайме

- Вручную исправленное нижнее подключение работает: агент вызывает HTTP-tool, `fromAIAgent("url"; "...")` подставляет URL, агент получает результат.
- `get_scenario` для правильного tool возвращает его внутри `AI Agent.parameters.tools`, вместе со сгенерированным `id`.
- В сломанных случаях `get_scenario` отдаёт бывший tool как обычный верхнеуровневый узел, в `prevNodes` которого имя AI Agent. Это и есть правый коннектор.
- Вложенный объект в `parameters.tools` сразу в `create_scenario` может нормализоваться в неправильное правое подключение.
- Добавление обычного следующего узла или смена конфигурации tool в том же `update_scenario` тоже воспроизводило смену коннектора.
- Повторное использование или явная передача `id` вложенного tool надёжно это не предотвращали.
- Минимальный граф из двух узлов (`run_once` → `ai_agent`), созданный сначала и затем отдельно обновлённый с `parameters.tools`, давал настоящий нижний tool. Поведение зависит от **порядка записи**, а не только от итогового payload.

### Ожидаемое поведение

Если узел передан внутри `AI Agent.parameters.tools`, `create_scenario` и `update_scenario` должны:

1. создавать и сохранять нижнее подключение Agent Tool;
2. сохранять его при добавлении или изменении параметров tool;
3. сохранять его при добавлении обычных узлов на правый выход агента;
4. отдавать граф через `get_scenario` без смены семантики коннектора;
5. оставлять `fromAIAgent(...)` валидным внутри tool.

API не должен молча превращать подключение Agent Tool в обычное последовательное ребро.

- Вручную исправленный рабочий граф: `6a8c2a1ff29d53def79b96f9`
- Минимальный рабочий Agent Tool, созданный через MCP: `6a8c2e978a4d88aa1a2e3c1d`

## Описание tool у AI Agent

Поле **не** видно в `search_node_types` у одиночного `http_request`. Оно появляется, когда узел уже **Agent Tool** (вложен в `parameters.tools`).

Ключ: `parameters.__$$internal__tool_description`.

Проверено 2026-09-03: и в первом `create_scenario` вместе с nested tool (`6a993320f4aedd6ed5b8d5a1`), и во втором `update` уже подключённого tool (`6a9932e014868f6504aeccde`) — `get_scenario` поле возвращает.

`get_dynamic_node_parameters` эту схему не отдаёт. Писать ключ вручную в nested `parameters`.

История: раньше запись на обычном HTTP (не как tool агента) отклонялась; верхний `description` на объекте tool выкидывался. Think/Plan по-прежнему имеют это поле сразу в live-схеме.

## Авторизация API-ключом у MCP Trigger не проверяется

Был создан сценарий с:

```json
{
  "use_authentification": true,
  "api_key": "mcp-full-qa-key-2026"
}
```

После активации JSON-RPC `initialize` на production MCP URL **без** заголовка авторизации вернул HTTP 200 и валидный результат initialize. Тот же сервер принял и авторизованного клиента и успешно выполнил tool.

Ожидаемое поведение: при `use_authentification: true` отсутствующий или неверный заголовок `Authorization` должен отклонять соединение.

Сценарий для воспроизведения: `6a8c2f4db3815fd0709abb69`.

## MCP HTTP-слой отсекает часть валидных шаблонных функций

Payload `update_scenario` с задокументированной функцией `substring(...)` был отвергнут MCP HTTP endpoint с HTTP 403 ещё до JSON-RPC ответа. Если убрать только выражение `substring(...)`, тот же update проходит.

Ожидаемое поведение: задокументированные функции Template Evaluator должны доходить до сервиса сценариев и там валидироваться/исполняться, а не блокироваться внешним HTTP-фильтром.

## Коннектор цикла Iterator сбрасывается, если в том же запросе есть узел после цикла

### Кратко

Рабочий цикл Iterator хранится как `Iterator.parameters.nodes = ["cycleRoot"]`, у корня цикла пустой `prevNodes`.

Если в `create_scenario` или `update_scenario` есть ещё обычный правый узел, у которого `prevNodes` указывает на Iterator, запись может стереть `parameters.nodes` и переписать корень цикла в `prevNodes: { iterator_0: {} }`. Это правый коннектор Iterator, не верхний cycle. Запуск тогда не итерирует (или зависает до отмены).

### Живые наблюдения (2026-09-01)

- Только массив: `6a96926af4aedd6ed5b8956a` — `set_variables_0` выполнился 5 раз.
- Объект: `6a969276be9f4245fc4f0333` — последний элемент `{key,value}`, цикл 2 раза.
- Цепочка из двух узлов без post-loop: `6a969314cd35afeff2407426` — `cycle_a_0` и `cycle_b_0` по 3 раза.
- Массив + post-loop в одном create: `6a969316cd35afeff2407430` — нет `parameters.nodes`, оба потомка на правом коннекторе.
- Цикл + post-loop в одном create: `6a969276be9f4245fc4f0329` — то же схлопывание; выполнение отменено через ~105 с.
- Добавление post-loop через `update_scenario` в уже рабочий массивный граф тоже стёрло `parameters.nodes`.

### Ожидаемое поведение

Запись ребра post-loop на правый коннектор Iterator должна сохранять `parameters.nodes` и пустой `prevNodes` у корней цикла.

**Ретест 2026-09-03:** ожидаемое поведение подтверждено (сценарии `6a9929e114868f6504aecc73`, `6a9929f281ea6a85fb2d21a6`).
